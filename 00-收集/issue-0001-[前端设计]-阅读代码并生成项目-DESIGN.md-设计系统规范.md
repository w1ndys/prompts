# [前端设计] 阅读代码并生成项目 DESIGN.md 设计系统规范

```
# 任务：阅读代码 → 理解项目 → 生成 DESIGN.md

你是一位同时精通前端开发和 UI/UX 设计的资深设计系统架构师。请忽略当前前端所有布局、颜色等设计，阅读业务代码后生成套适合该项目的完整前端开发规范

## 第一步：阅读并理解（不要跳过，必须先完成）

请通读项目代码，从以下维度分析并输出你的理解：

### 业务维度
- 这个产品的核心价值是什么？
- 属于什么行业/领域？
- 目标用户群体是谁？（他们的技术水平、使用频率、核心诉求）
- 核心使用场景是什么？（高频操作？偶尔查看？移动优先？）

### 技术维度
- 技术栈是什么？（框架、UI 库、CSS 方案）
- 有没有已在使用的设计相关依赖？（如 Ant Design、Tailwind、shadcn）
- 项目结构如何？（页面数量、组件复杂度、路由层级）

### 界面维度
- 有哪些核心页面/模块？各自的功能是什么？
- 信息密度如何？（数据表格多？表单多？卡片列表多？富文本多？）
- 交互复杂度如何？（简单 CRUD？拖拽？实时协作？复杂工作流？）
- 导航结构是什么样的？（侧边栏？顶栏？面包屑？标签页？）

### 情感维度（从代码推断）
- 这个产品应该给用户什么感觉？（专业严肃？轻松友好？极客酷感？）
- 参考同类产品，什么设计风格最适合？

## 第二步：设计决策（基于你的理解做出判断）

在生成具体规范前，先明确以下设计决策并解释理由：

| 决策点 | 你的选择 | 理由 |
|--------|---------|------|
| 整体调性 | 如：现代极简 + 专业可信 | 因为这是 toB 的 ... |
| 色调方向 | 如：冷色系（蓝/靛） | 因为行业是 ... |
| 信息密度 | 如：中等偏紧凑 | 因为核心场景是数据分析 |
| 圆角风格 | 如：中等圆角（8px） | 因为希望兼顾专业感和亲和力 |
| 阴影使用 | 如：克制使用 | 因为内容密集，过多阴影会增加视觉噪音 |
| 动效策略 | 如：功能性动效为主 | 因为用户高频操作，花哨动效会打断流程 |
| 主要模式 | 如：亮色为主，支持暗色 | 因为 ... |

## 第三步：输出完整 DESIGN.md

遵循 Google Stitch DESIGN.md 标准格式，输出以下 9 大模块：

### 1. Visual Theme & Atmosphere
- 设计哲学（一段话概括）
- 视觉关键词（3-5 个）
- 参考方向（最像哪些产品的设计气质）

### 2. Color Palette & Roles
- 品牌主色 + 辅色（含 HEX）
- 中性色阶（8-10 级，从白到深灰/黑）
- 语义色（Success / Warning / Error / Info，各含浅底色 + 深前景色）
- 表面色层级（背景 → 卡片 → 悬浮层）
- 暗色模式完整色板
- CSS 变量命名

### 3. Typography Rules
- 字体族（英文 + 中文 + 等宽，含完整回退栈）
- 完整字号层级表：

  | Token | Size | Weight | Line Height | Letter Spacing | Use Case |
  |-------|------|--------|-------------|----------------|----------|
  | display | ... | ... | ... | ... | 大标题 |
  | h1-h6 | ... | ... | ... | ... | ... |
  | body-lg | ... | ... | ... | ... | ... |
  | body | ... | ... | ... | ... | 正文 |
  | body-sm | ... | ... | ... | ... | ... |
  | caption | ... | ... | ... | ... | 辅助文字 |

- 段落最大宽度、行高比例
- 中文特殊处理规则

### 4. Component Stylings
为以下组件定义完整规范（含所有状态和变体）：
- Button（Primary / Secondary / Ghost / Danger / Link × sm/md/lg × 所有状态）
- Input / TextArea / Select（默认/聚焦/错误/禁用）
- Card（边框/阴影选择、内边距、悬浮效果）
- Table（行高、斑马纹、悬浮行、固定表头）
- Navigation（顶栏/侧栏/面包屑 + 激活/悬浮/折叠态）
- Modal / Drawer（遮罩、尺寸、动画）
- Toast / Alert / Badge（位置、持续时间、变体）
- Tag / Chip（颜色变体、可关闭状态）
- Tabs（风格、激活态指示器）
- Pagination
- Empty State / Loading State

### 5. Layout Principles
- 基础间距单元（4px 或 8px）
- 间距阶梯表（含 Token 名）
- 页面布局（侧栏宽度、内容最大宽度、页面边距）
- 网格系统

### 6. Depth & Elevation
- 3-5 级阴影定义（含 CSS box-shadow 值）
- 各级使用场景
- z-index 规范表

### 7. Design Do's and Don'ts
- 至少 8 条"不要做"的明确禁令
- 至少 5 条"要做"的最佳实践
- 针对这个项目特有的设计护栏

### 8. Responsive Behavior
- 断点定义（mobile / tablet / desktop / wide）
- 各断点下的布局变化
- 触摸目标最小尺寸
- 导航折叠策略

### 9. Agent Prompt Guide
- 核心色彩速查表（直接复制使用）
- CSS 变量完整列表
- Tailwind Token 映射（如果项目使用 Tailwind）
- 给 AI 的快速提示词模板

## 输出格式要求
- 纯 Markdown
- 所有色值给 HEX（暗色模式也要）
- 所有尺寸给 px 和 rem 双值
- 组件样式用表格呈现
- 文件开头必须有 "## Project Understanding" 让我确认理解是否正确
```
