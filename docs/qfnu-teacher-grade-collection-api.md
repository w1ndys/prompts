# 强智教务系统教师端成绩采集 API

## 1. 接口范围

本接口用于已授权的教师账号只读查询班级成绩，供内部成绩快照和统计服务使用。

支持：

- 发现院系、年级、专业、行政班和学期选项；
- 按行政班和学期分页查询学生课程成绩；
- 对查询结果执行总页数、总条数和字段完整性校验。

不支持：

- 成绩录入、修改、删除；
- 对外提供完整成绩榜单；
- 通过浏览器直接使用教师账号；
- 将教师账号凭据、Cookie 或验证码暴露给调用方。

## 2. 基本约定

- 基础地址：`http://zhjw.qfnu.edu.cn`
- 根路径：`/jsxsd/`
- 默认请求头：`User-Agent: Mozilla/5.0`
- 请求编码：`application/x-www-form-urlencoded`
- 响应编码：UTF-8
- 所有请求使用同一个 Cookie 会话。
- 常见会话 Cookie 包括 `JSESSIONID` 和 `sto-id-20480`，具体值由服务器下发，调用方不得自行构造。
- 每次采集任务使用独立 Cookie Jar，任务结束立即销毁。
- 登录状态验证和业务请求禁止自动跟随重定向。
- 上游服务为 HTTP，采集器只能运行在受控服务端；对外服务必须使用 HTTPS。

## 3. 登录流程

登录流程必须按以下顺序执行，并在整个流程中复用同一 Cookie 会话。

### 3.1 初始化会话

~~~http
GET /
User-Agent: Mozilla/5.0
~~~

HTTP 状态码小于 400 时进入下一步，并保存响应中的 Cookie。

### 3.2 获取验证码

~~~http
GET /verifycode.servlet
User-Agent: Mozilla/5.0
~~~

成功条件：

- HTTP 状态码为 200；
- 响应体非空；
- 响应体为验证码图片二进制数据。

验证码图片只在当前登录流程内存中使用，不落盘。

### 3.3 获取会话随机参数

~~~http
POST /Logon.do?method=logon&flag=sess
Content-Type: application/x-www-form-urlencoded
User-Agent: Mozilla/5.0

（空请求体）
~~~

成功响应为纯文本：

~~~text
<scode>#<sxh>
~~~

`scode` 和 `sxh` 均不能为空。响应为空、为 `no`（不区分大小写）或无法按 `#` 拆分时，当前登录轮次失败。

### 3.4 生成 encoded 参数

输入：

- 用户名；
- 密码；
- `scode`；
- `sxh`。

步骤：

1. 拼接 `username + "%%%" + password`；
2. 遍历拼接后的明文；
3. 对索引 0 至 19 的字符，先写入当前字符；
4. 如果 `sxh` 同一索引位置是数字 `n`，则从 `scode` 当前游标顺序取出 `n` 个字符追加，并推进游标；
5. `scode` 耗尽后停止追加；
6. 索引 20 及之后的字符直接追加，不再插入 `scode`。

示例：

~~~text
scode = ABC123
sxh = 201
username = u
password = p
明文 = u%%%p
encoded = uAB%C%p
~~~

### 3.5 提交登录

~~~http
POST /Logon.do?method=logonLdap
Content-Type: application/x-www-form-urlencoded
User-Agent: Mozilla/5.0

userAccount=
userPassword=
RANDOMCODE=<验证码文本>
encoded=<编码后的凭证>
~~~

按响应正文判断：

| 响应特征 | 处理 |
|---|---|
| 包含“密码错误”“用户名或密码错误”“用户名密码错误”或“您提供的用户名或者密码有误” | 账号密码错误，立即终止 |
| 包含“验证码错误”或“验证码不正确” | 当前轮次失败，重新初始化会话并获取新验证码 |
| 不包含上述错误 | 进入主页状态验证 |

### 3.6 教师主页状态验证

~~~http
GET /jsxsd/framework/jsMain.jsp
User-Agent: Mozilla/5.0
~~~

成功条件：

- HTTP 状态码为 200；
- 响应正文包含“教学一体化服务平台”或“glyphicon-class”。

出现以下任一情况均视为登录失败：

- 301/302 等重定向；
- 非 200 状态码；
- 缺少成功标识；
- 响应同时包含“请输入账号”“请输入密码”“请输入验证码”。

验证码错误时，从 3.1 重新开始，完整登录流程最多执行 3 轮。

## 4. 通用重试规则

仅以下情况允许有限重试：

- 请求超时；
- 连接被拒绝；
- 连接被重置；
- broken pipe；
- HTTP 429；
- HTTP 5xx。

建议单步最多重试 3 次，重试间隔约 1 秒。业务失败不得按网络错误重试。

以下情况立即终止当前任务：

- 账号密码错误；
- 教师账号无权限；
- 检测到账号在其他位置登录；
- 响应结构无法识别；
- 连续达到重试上限。

## 5. 接口总览

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/jsxsd/cjgl/bjcjck_query` | 获取成绩查询表单和服务端字典 |
| POST | `/jsxsd/cjgl/bjcjck_query` | 按级联条件刷新专业和行政班 |
| POST | `/jsxsd/cjgl/bjcjck_list` | 分页查询行政班成绩 |
| POST | `/jsxsd/cjgl/bjcjk_print` | 打印页面，不作为采集接口 |
| GET | `/jsxsd/cjgl/fdycjcx.do` | 辅导员成绩查询，当前不纳入采集协议 |

## 6. 成绩查询条件接口

### 6.1 获取查询表单

~~~http
GET /jsxsd/cjgl/bjcjck_query
User-Agent: Mozilla/5.0
~~~

响应为 HTML 页面，页面标题通常为“班级成绩查看”。查询表单字段使用以下名称：

| 字段 | 含义 | 值说明 |
|---|---|---|
| `xsyx` | 院系 | 服务端下发的编码，可能为短码、5 位码或 32 位十六进制 Token |
| `xsnj` | 年级 | 4 位年份 |
| `xszy` | 专业 | 服务端下发的 32 位十六进制 Token |
| `xzbh` | 行政班 | 服务端下发的 32 位十六进制 Token |
| `xnxq` | 学年学期 | `YYYY-YYYY-N` |
| `kcxz` | 课程性质 | 服务端下发的筛选值，可为空 |
| `cjbs` | 成绩标志 | 服务端下发的筛选值，可为空 |
| `ksxz` | 考试性质 | 服务端下发的筛选值，可为空 |
| `kch` | 课程编号 | 可为空 |
| `kcmc` | 课程名称 | 可为空 |
| `op` | 隐藏操作字段 | 按页面原值回传，通常为空 |

解析器必须按 `name` 或 `id` 定位字段，不得依赖选项顺序或 HTML 的固定列位置。

### 6.2 级联刷新

~~~http
POST /jsxsd/cjgl/bjcjck_query
Content-Type: application/x-www-form-urlencoded
Referer: /jsxsd/cjgl/bjcjck_query

xsyx=<院系编码>&xsnj=<年级>&xszy=<专业编码>&xzbh=<行政班编码>&xnxq=<学期>&op=&kch=&kcmc=&kcxz=&cjbs=&ksxz=
~~~

级联规则：

- 只提交 `xsnj`：返回该年级的专业列表；
- 提交 `xsyx + xsnj`：返回该院系该年级的专业和行政班列表；
- 提交 `xsyx + xsnj + xszy`：用于读取该专业对应的行政班列表；
- 所有 Token 必须原样回传，不能由客户端生成；
- 服务端返回完整 HTML，调用方只提取下拉选项，不保存原始响应。

推荐发现顺序：

~~~text
读取全部 xsyx、xsnj、xnxq
→ 从服务端年级选项中选择目标年级
→ 对每个 xsyx + xsnj 读取 xszy
→ 对每个 xszy 读取 xzbh
→ 对每个 xzbh 和适用 xnxq 查询成绩
~~~

## 7. 班级成绩列表接口

### 7.1 第 1 页

~~~http
POST /jsxsd/cjgl/bjcjck_list
Content-Type: application/x-www-form-urlencoded
Referer: /jsxsd/cjgl/bjcjck_query

xsyx=<院系编码>
xsnj=<年级>
xszy=<专业编码或空>
xzbh=<行政班编码>
xnxq=<学期>
op=
kch=
kcmc=
kcxz=
cjbs=
ksxz=
~~~

首页可以省略 `pageIndex`，默认查询第 1 页。

### 7.2 后续页

列表页通常包含以下隐藏字段：

~~~text
xzbh
kcmc
kcxz
cjbs
ksxz
xnxq
kch
zcj
zcjfh
ksxnxq
jsxnxq
~~~

后续请求至少提交：

~~~http
POST /jsxsd/cjgl/bjcjck_list
Content-Type: application/x-www-form-urlencoded
Referer: /jsxsd/cjgl/bjcjck_list

xzbh=<行政班编码>&xnxq=<学期>&pageIndex=2
~~~

建议同时按上一页表单原值补齐其他隐藏字段。

- `pageIndex` 从 1 开始；
- 实测每页 20 行；
- 最后一页可以少于 20 行；
- 翻页通过递增 `pageIndex` 完成，不需要执行页面 JavaScript。

## 8. 响应表格

响应类型为 UTF-8 `text/html)，主数据表格通常带有：

~~~html
<table class="Nsb_r_list Nsb_table">
~~~

解析前必须校验表头和列数量。每行代表一名学生的一门课程成绩。

### 8.1 字段定义

| 序号 | 表头 | 数据类型/示例 | 处理 |
|---:|---|---|---|
| 1 | 序号 | 页内数字 | 丢弃 |
| 2 | 学号 | 通常为 10 位数字 | 规范化后生成 HMAC 索引；必要时单独加密 |
| 3 | 姓名 | 中文姓名 | 解析后立即丢弃 |
| 4 | 开课学期 | `YYYY-YYYY-N` | 保留 |
| 5 | 班级名称 | 文本 | 保留为展示字段 |
| 6 | 课程编号 | 通常为 6 位数字 | 保留；全局唯一性由业务层验证 |
| 7 | 课程名称 | 文本 | 保留 |
| 8 | 总成绩 | 数字或等级文字 | 保留原文并标记成绩类型 |
| 9 | 成绩标志 | 编码或空 | 保留 |
| 10 | 课程性质 | 文本 | 保留 |
| 11 | 课程属性 | 文本 | 保留 |
| 12 | 学时 | 数字 | 保留 |
| 13 | 学分 | 整数或小数 | 保留 |
| 14 | 开课单位 | 文本 | 保留 |
| 15 | 录入人 | 可能为教师姓名 | 解析后立即丢弃 |
| 16 | 考试性质 | 文本 | 保留 |
| 17 | 补重学期 | 文本或空 | 保留 |
| 18 | 备注 | 文本或空 | 保留 |

### 8.2 行与重修语义

- 同一学生会连续出现多行；
- 学生记录边界可能跨页；
- 同一课程可能因补考、重修或重补出现多次尝试；
- 采集器必须保留成绩尝试维度；
- 重修取值、绩点换算和是否计入排名由业务规则单独定义；
- 教师成绩表没有绩点列，调用方不得假定上游返回绩点。

## 9. 分页完整性

页面页脚通常包含：

~~~text
共{total_pages}页 {total_rows}条
~~~

调用方必须：

1. 解析 `total_pages` 和 `total_rows`；
2. 从第 1 页读取到第 `total_pages` 页；
3. 统计成功解析的实际页数和行数；
4. 校验实际页数等于 `total_pages`；
5. 校验实际行数等于 `total_rows`；
6. 校验每页表头和字段数量；
7. 任一校验失败时，将本次班级/学期采集标记为失败。

不完整的结果不得替换或删除已有成绩快照。空结果应在确认页面结构后作为 0 条成功结果处理。

## 11. 采集完整流程

~~~text
独立登录教师账号
→ 获取查询表单和服务端字典
→ 发现目标年级、院系、专业和行政班
→ 对每个行政班和适用学期请求第 1 页
→ 根据页脚读取总页数
→ 逐页递增 pageIndex
→ 校验页数、行数、表头和字段
→ 解析后立即丢弃姓名和录入人
→ 对学号生成 HMAC 索引并按要求加密
→ 写入临时成绩快照
→ 完整性校验通过后再发布或替换对应范围
~~~

采集任务要求：

- 同一时间只运行一个全局采集任务；
- 每个任务使用独立 Cookie 会话；
- 单班失败与整批失败分开记录；
- 不完整班级不得标记为成功；
- 任务结束后销毁 Cookie Jar；
- 日志只能记录阶段、数量、耗时和错误类别。

## 12. 安全要求

- 姓名和录入人解析后立即丢弃；
- 学号至少使用服务端密钥 HMAC 作为关联索引；
- 如需管理端恢复明文学号，必须使用独立字段密钥加密；
- 教务密码、Cookie、验证码图片、OCR 文本和原始 HTML 不得写入日志或数据库；
- 不得向普通用户返回同学姓名、学号、成绩和完整排行榜；
- 原始成绩文件和备份必须使用受限权限及加密存储；
- 采集器不得把任何教师凭据发送到浏览器；
- 对外 API 必须使用 HTTPS；
- 登录、采集和查询接口应设置超时、限流、审计和告警。

## 13. 待确认项目

以下行为需要使用实际教师账号和代表性数据进一步确认：

- 教师账号的成功、密码错误和验证码错误响应；
- 教师账号实际可查询的院系和年级范围；
- 选择 `xszy` 后 `xzbh` 的过滤准确性；
- `xszy` 和 `xzbh` Token 的跨会话稳定性；
- 空班级或无成绩学期的页面结构；
- 缓考、缺考、违纪、舞弊、取消考试资格记录的成绩表现；
- 补考、重修、重补记录及补重学期格式；
- 课程编号是否必须与开课单位组合；
- 实际请求频率、最大并发、429 触发条件和安全重试间隔；
- 百分制、等级制和重修成绩的最终业务计算规则。
